## Overview

A working toolkit for building software with AI coding agents (programs such as Claude Code and Codex that read files, run commands and edit code under a person's direction). It holds the commands, skills, sub-agents, output styles, templates and standards the author uses to plan, build, review and document software.

The three dotted folders are laid out exactly as a project expects them, so installing is a copy:

| Copy this folder | Into your project as | You get |
|---|---|---|
| `.claude/` | `.claude/` | slash commands, sub-agents, skills and output styles for Claude Code |
| `.codex/` | `.codex/` | the same sub-agents for Codex |
| `.agents/` | `.agents/` | the files the commands read while running, and the templates a new project starts from |

`rules/`, `prompts/` and `scripts/` are not installed; they are used by copying a file or running a script.

Codex has no slash commands. To run a command or a skill there, say: "Read and follow in full `<path to its file>` with this additional context:".

Five files are adapted from the Dynamous Agentic Coding course by Cole Medin, and the two codebase setup specifications take their step sequence from its Live Workshop #2. Everything else is the author's own work. MIT licence.

## Key Features

- Four chains of commands and skills that pass work through files on disk: a planning chain from problem definition to executed plan, a pre-merge review chain, a worktree workflow, and a foundation build driven by a specification
- Every command and sub-agent generated from a shared template, so each declares its inputs, ordered process, decision discipline and exactly one output shape
- Sub-agents for independent option generation, evidence-based ranking and review of a document against the communication standard, with Codex equivalents generated by script
- Project templates that take a new application from idea intake, through blueprint, to a repository foundation built in validated, committed steps
- A single communication standard for an agent's messages to the user and the documents it writes

## Documents

Each item below is a top-level folder. Its own README lists the files inside it.

- [`.claude/commands/`](.claude/commands/README.md): **Claude Code slash commands** — commands organised in groups; the group folder is the command namespace (`git/commit.md` is `/git:commit`). Copy to a project's `.claude/commands/`.
- [`.claude/agents/`](.claude/agents/README.md): **Claude Code sub-agents** — `document-reviewer`, `navigator` and `pathfinder`. Copy to a project's `.claude/agents/`.
- [`.claude/skills/`](.claude/skills/README.md): **Claude Code skills** — `check-ignore-comments`, which reports on every comment that switches off a code check, `new-worktree` and `merge-worktrees`, which start and finish a piece of work in its own worktree, `task-structuring`, which turns a rough request into a tightly scoped work brief for another LLM, and `technical-code-review`, which audits code changes and writes a review report; run each as `/<name>`. Copy to a project's `.claude/skills/`, or to `~/.claude/skills/` to use it in every project; `check-ignore-comments` and `technical-code-review` also need the project files they read copied into each project.
- [`.claude/output-styles/`](.claude/output-styles/README.md): **Claude Code output styles** — `project-ideator`, which shapes a vague software idea into one Objective with measurable Key Results. Copy to a project's `.claude/output-styles/`, or to `~/.claude/output-styles/` to use it in every project.
- [`.codex/`](.codex/README.md): **Codex sub-agents** — the same three sub-agents in TOML, generated from the Claude versions and never edited by hand. Copy to a project's `.codex/`.
- [`.agents/reference/`](.agents/reference/README.md): **Reference standards and guides** — the command and sub-agent templates, the communication standard, the rules the review chain audits against, the planning framework and the worktree setup. Copy to a project's `.agents/reference/`; several commands read these files by that path.
- [`.agents/templates/`](.agents/templates/README.md): **Project templates** — idea intake, project blueprints, README and `CLAUDE.md` templates shared by every kind of project, and two codebase setup specifications that build a repository's foundation in twelve validated, committed steps: one for a Python backend (FastAPI, Supabase and Docker) and one for an Obsidian plugin in TypeScript. Each specification supplies its own stack's validation checks and README and `CLAUDE.md` content. The Obsidian plugin specification has improvements the Python one lacks, so bring those across before building the next Python backend. Copy to a project's `.agents/templates/`.
- [`rules/`](rules/README.md): **Global rules and personas** — a stack-independent `CLAUDE.md` for repositories that are not applications, and three chat persona prompts.
- [`prompts/`](prompts/README.md): **Standalone prompts** — five prompts pasted into a chat, including the two that generated the blueprint templates.
- [`scripts/`](scripts/README.md): **Scripts** — the Claude-to-Codex sub-agent converter and its tests.

## Maintenance

When adding or changing files in this repository:

- Keep each folder's README in sync with the files it holds, and keep this README's folder list in sync with the folders.
- Decide what a new set of instructions becomes by asking these questions in order and stopping at the first yes:
  - Should it govern every reply of a session, as a role, a tone or a way of holding the whole conversation? Make it an output style. One is active at a time, and it can drop Claude Code's built-in coding instructions.
  - Should the work go to a separate helper that sees none of the conversation and reports back? Make it a sub-agent. Use one where the work needs a view independent of the conversation, or would crowd it.
  - Is it a task called for partway through other work, which needs supporting files of its own or which Claude should be able to start unasked? Make it a skill, a folder that carries those files with it.
  - Is it a single file run only by typing its name, such as one step in a chain run by hand? Make it a command.
- Create commands with `/meta:create-command` and sub-agents with `/meta:create-agent` so they follow the shared templates; do not draft them freehand. Draft a skill by converting an existing command.
- After changing a Claude sub-agent, regenerate its Codex file with the script in `scripts/` and run the tests there.
- Keep every path project-relative or home-relative; never commit a machine-specific path, a credential or a `.env` file.
- Every README in this repository uses the same sections in this order: Badges, Overview, Key Features, Documents, Maintenance, under a title ending in "— Reference".
